# 商品中心首期设计规格

## 1. 背景与目标

当前 ERP 已具备订单导入、SKU 映射校验、库存锁定和异常订单工作台，但商品主数据只有后端基础骨架，缺少完整的维护、导入、渠道商品同步和映射操作能力。

商品中心首期目标是建立独立于电商平台的统一 SPU/SKU 主数据，并同时支持 Excel 导入和国内八个平台商品只读拉取。商品中心完成后，应能关闭“平台商品未映射到内部 SKU”这一订单异常闭环，并为库存、采购、履约和业财模块提供稳定的商品基础。

首期接入平台：

- 微信视频号小店
- 淘宝/天猫
- 京东
- 抖音
- 小红书
- 快手小店
- 得物
- 拼多多

## 2. 范围边界

### 2.1 首期包含

- SPU、SKU、规格、条码、品牌、类目、图片、计量单位和扩展属性
- 商品草稿、启用、停用、归档生命周期
- 企业统一内部 SKU 编码及全局唯一校验
- Excel 模板下载、预检、批量导入、错误报告和结果导出
- 八个平台商品、SKU、图片、类目和上下架状态的只读拉取
- 平台原始数据归档及统一商品模型转换
- 渠道 SKU 与内部 SKU 的自动精确匹配、人工确认和冲突处理
- 平台图片向 ERP 自有对象存储归档
- 商品同步任务、失败重试、操作审计和权限控制
- SKU 映射完成后重新处理现有异常订单

### 2.2 首期不包含

- 向平台发布或修改商品
- 向平台回写价格、库存和上下架状态
- 完整平台类目模板及平台属性校验引擎
- 组合装、赠品和套装组件清单
- 批次、效期、序列号和唯一码的完整作业逻辑
- 商品成本核算、采购价格和订单利润
- 智能图片识别或模糊匹配结果的自动确认

这些能力分别在平台商品发布、库存、采购和业财阶段扩展，首期数据结构保留扩展空间。

## 3. 设计原则

1. 内部 SKU 是库存、采购、履约和业财核算的唯一商品主体，不依赖任何平台编码。
2. 平台商品与内部商品分层保存，平台上下架不得直接改变内部商品状态。
3. 平台适配器只负责授权、限流、分页、原始数据获取和字段转换，不承载商品领域规则。
4. 所有同步、导入和映射操作必须幂等、可追踪、可重试和可审计。
5. 已被业务单据引用的商品不得物理删除，只能停用或归档。
6. 自动映射仅限能够证明唯一性的精确匹配；不能证明唯一性的结果必须人工确认。

## 4. 领域模型

### 4.1 SPU

SPU 表示共享品牌、类目、名称和图片的一组商品。每个 SKU 必须属于一个 SPU。Excel 或平台数据缺少可用 SPU 信息时，系统为导入批次自动创建默认 SPU，避免阻断历史数据迁移。

主要字段：

- `spu_code`：企业内部 SPU 编码，全局唯一
- `name`：商品名称
- `brand_id`、`category_id`
- `status`：`DRAFT`、`ACTIVE`、`DISABLED`、`ARCHIVED`
- `attributes`：内部可扩展属性
- 创建人、创建时间、更新人、更新时间和版本号

### 4.2 SKU

SKU 是库存与履约最小主体。内部 SKU 编码由企业定义，在手工新增或 Excel 导入时提供，并由系统校验全局唯一。

主要字段：

- `sku_code`：企业内部 SKU 编码，全局唯一且创建后不可直接修改
- `spu_id`
- `barcode`：条码；非空条码必须全局唯一
- `specifications`：颜色、尺码等规格
- `unit`
- `status`
- 为批次、效期和序列号策略预留的配置字段
- 创建人、创建时间、更新人、更新时间和版本号

SKU 编码确需变更时，后续通过受控的“换码”业务完成；首期不允许直接覆盖，以免破坏历史关联。

### 4.3 渠道商品与渠道 SKU

渠道商品保存平台返回的数据，不与内部 SPU/SKU 合并：

- 平台、店铺和平台商品 ID
- 平台标题、品牌、类目、图片及上下架状态
- 平台商品修改时间和 ERP 最近同步时间
- 统一转换字段
- 原始响应对象存储地址、摘要和平台请求标识

渠道 SKU 保存平台 SKU ID、规格、条码、价格快照和平台状态。价格只作为平台同步快照展示，首期不参与内部价格或财务核算。

### 4.4 渠道 SKU 映射

一个内部 SKU 可以映射多个平台、店铺及平台 SKU；同一平台、同一店铺的一个平台 SKU 只能存在一个有效内部 SKU 映射。

映射记录包含：

- 平台、店铺、平台商品 ID 和平台 SKU ID
- 内部 SKU
- 映射来源：精确自动匹配、人工确认或 Excel 导入
- 匹配依据及置信说明
- 状态、生效时间、操作人和操作原因

解除映射不物理删除记录，而是终止其有效期并保存审计历史。

### 4.5 图片

商品图片保存 ERP 对象存储地址、平台原始地址、来源、排序、内容摘要和下载状态。页面优先使用 ERP 自有图片。图片下载失败不阻断商品同步，而是生成可重试的图片补偿任务。

## 5. 数据存储

在现有 `erp-masterdata` 模块内增量扩展，不删除或重建现有订单、SKU 和映射数据。

核心表：

- `md_spu`
- 扩展现有 `md_sku`
- `md_product_image`
- `md_channel_product`
- `md_channel_sku`
- 扩展现有 `md_channel_sku_mapping`
- `md_import_job`
- `md_import_error`
- `md_product_sync_job`
- `md_product_sync_item`
- `audit_log`

主要唯一约束：

- SPU 编码全局唯一
- 内部 SKU 编码全局唯一
- 非空条码全局唯一
- 平台、店铺、平台商品 ID 唯一
- 平台、店铺、平台 SKU ID 唯一
- 同一渠道 SKU 同一时间只能有一个有效内部 SKU 映射
- 导入批次、同步任务和平台分页请求均使用幂等键

平台原始大对象及图片保存到对象存储；数据库保存地址、摘要、版本及查询所需字段。

## 6. 平台适配架构

商品中心定义统一只读连接器契约：

- 分页拉取商品
- 拉取单个商品详情
- 拉取商品下的 SKU
- 获取平台类目和状态的原始值
- 返回限流、授权失效、临时失败和永久数据错误的标准结果

每个平台分别实现授权、签名、分页游标、限流和字段转换。平台适配器不得直接写商品主数据，统一同步服务负责幂等落库、状态更新、图片归档和映射建议生成。

首期八个平台均实现这一契约，但可按店铺分别启用。未取得生产资质或授权的平台保留禁用状态，不能用模拟数据冒充生产同步成功。

## 7. 映射规则

自动映射按以下顺序执行：

1. 渠道 SKU 的有效条码与唯一内部 SKU 条码完全一致。
2. 渠道 SKU 编码与唯一内部 SKU 编码完全一致。
3. 其他情况只生成候选建议，不自动确认。

存在重复条码、重复编码、一个渠道 SKU 命中多个内部 SKU，或者既有映射与新结果冲突时，记录为映射冲突并进入人工工作台。

商品名称、规格文本和图片只能用于排序候选建议，不能作为首期自动映射依据。

映射确认后发布 `ChannelSkuMapped` 领域事件。订单模块消费该事件，对 `SKU_NOT_MAPPED` 异常订单执行幂等重处理。若订单仍存在库存不足或其他异常，应保留在对应异常队列，不得强制转为正常。

## 8. 页面与用户流程

### 8.1 商品列表

- 按商品名称、SPU、SKU、条码、品牌、类目和状态查询
- 展示主图、SPU、SKU 数量、渠道映射数量及更新时间
- 新增、编辑、启停、归档、导入和导出
- 进入商品详情和渠道关联视图

### 8.2 商品详情

- 维护 SPU 基本资料、图片和扩展属性
- 在同一页面维护多个 SKU、规格、条码和状态
- 查看关联平台、店铺、渠道商品和历史变更
- 被业务单据引用的 SKU 不提供物理删除操作

### 8.3 渠道商品池

- 按平台、店铺、同步状态、平台上下架状态和映射状态筛选
- 查看平台原始字段、统一字段和最近同步结果
- 手动同步店铺或单个商品
- 查看失败原因并重试

### 8.4 SKU 映射工作台

- 未映射、系统建议、已映射和映射冲突四类视图
- 并排展示平台商品与内部 SKU 信息
- 搜索内部 SKU、确认建议、批量映射和解除映射
- 所有修改及解除操作要求填写原因

### 8.5 导入导出中心

导入采用“上传、预检、确认、执行、结果”五步流程。预检不得修改业务数据。结果区分新增、更新、跳过、冲突和失败，并允许下载逐行错误报告。

单行数据失败不影响其他合法行。确认后的合法行按受控批次写入；已被订单引用的数据不支持简单全批回滚，修正必须通过新的变更批次完成。

### 8.6 同步任务中心

- 展示平台、店铺、任务类型、进度、游标、结果和最近错误
- 支持人工同步和失败任务重试
- 保存平台请求标识、标准错误码和脱敏错误信息
- 授权失效时停止对应店铺任务并通知管理员

## 9. 权限与审计

角色能力：

- 商品管理员：新增、编辑、启停、归档、导入、确认及解除映射
- 商品运营：查看、编辑普通资料、执行同步和提交映射建议
- 只读用户：查看及在授权范围内导出
- 系统管理员：管理店铺授权、同步配置和失败任务

启停、归档、批量导入、确认映射、解除映射和失败任务强制重试属于重要操作，必须记录操作人、时间、原因、关联批次及变更前后值。店铺授权令牌、消费者隐私数据和平台密钥不得进入审计明文。

## 10. API

首期管理 API：

- `/api/products/spus`：SPU 查询、新增、编辑、启停及归档
- `/api/products/skus`：SKU 查询、新增、编辑及状态管理
- `/api/channel-products`：渠道商品查询及详情
- `/api/channel-products/sync-jobs`：创建、查询和重试同步任务
- `/api/sku-mappings`：查询建议、确认、批量映射及解除映射
- `/api/product-imports`：上传、预检、确认导入及下载错误报告
- `/api/product-exports`：创建导出任务及下载结果
- `/api/order-exceptions/{id}/retry`：手动触发单个异常订单幂等重处理

批量和同步类 API 创建异步任务并立即返回任务 ID，不在 HTTP 请求内完成万行导入或平台全量同步。

## 11. 错误处理与恢复

- 重复 SKU、重复条码和映射冲突阻止对应记录写入并提供明确错误位置。
- 平台限流按平台返回值和本地退避策略延迟重试。
- 临时网络错误自动重试，永久数据错误进入人工处理。
- 授权过期停止该店铺后续同步，不影响其他店铺。
- 图片归档失败进入补偿队列，不回滚已同步商品。
- 同步任务支持从已持久化游标继续，不重复写入已完成分页。
- 平台商品删除或下架只更新渠道状态，不删除内部商品或历史映射。
- 所有任务保留原始数据摘要、执行记录和最后一次错误，便于重放和审计。

## 12. 性能与运行约束

- 商品列表、渠道商品池和映射工作台必须服务端分页。
- 万行级 Excel 导入作为异步任务执行，不阻塞页面请求。
- 平台同步按平台和店铺隔离限流，一个店铺失败不得阻塞其他店铺。
- 图片下载与商品结构化落库解耦。
- 查询索引至少覆盖内部 SKU、条码、平台/店铺/平台商品 ID、平台 SKU ID、状态和更新时间。

## 13. 测试策略

### 13.1 后端

- SPU/SKU 状态、唯一约束和并发更新单元测试
- Excel 预检、部分失败、重复提交和错误报告集成测试
- 八个平台连接器契约测试
- 分页恢复、限流、授权过期和幂等重试测试
- 自动映射、候选建议、冲突和解除映射测试
- 映射事件触发订单异常重处理的端到端测试
- 对象存储图片归档及补偿任务测试

### 13.2 前端

- 商品列表筛选、分页和状态操作组件测试
- 商品详情 SPU/SKU 编辑及校验测试
- 导入五步流程及错误下载测试
- 渠道商品同步和失败重试测试
- 映射确认、批量操作、冲突和权限限制测试

### 13.3 浏览器验收

- 手工创建并启用 SPU/SKU
- Excel 预检、确认导入和失败报告下载
- 八个平台分别创建可追踪同步任务
- 渠道 SKU 自动精确匹配及人工确认
- 映射完成后异常订单重新进入处理流程
- 停用或归档商品后历史订单仍可查询
- 越权操作被拒绝且重要操作产生审计记录

## 14. 验收标准

1. 用户可以通过页面和 Excel 创建、修改、查询及导出 SPU/SKU。
2. 每个 SKU 都归属一个 SPU，内部 SKU 编码和有效条码满足唯一约束。
3. 八个平台均具备统一只读商品同步适配器及可追踪任务；未授权平台明确显示不可用。
4. 重复导入、重复分页和重复任务重试不会生成重复商品、SKU 或映射。
5. 自动映射只发生在唯一精确条码或编码匹配时。
6. 映射完成后，相关 SKU 未映射异常订单能够被幂等重新处理。
7. 停用、归档和平台下架均不会破坏历史订单查询。
8. 平台失败、限流、授权过期和图片归档失败均可定位并按规则恢复。
9. 重要操作具有权限校验和完整审计记录。
10. 万行级 Excel 导入和平台分页同步作为异步任务运行，不阻塞普通页面请求。
11. 后端单元及集成测试、前端组件测试和核心浏览器流程全部通过。

## 15. 实施分段

商品中心采用三个可独立验收的实施段：

1. 内部商品主数据、Excel 导入导出和商品管理页面。
2. 渠道商品统一契约、同步任务及八个平台只读适配器。
3. SKU 映射工作台、异常订单重处理、审计、性能和完整验收。

各段均必须完成数据库迁移、后端接口、前端页面、自动化测试和浏览器验收后，才能进入下一段。
